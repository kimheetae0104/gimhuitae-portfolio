02 · PROBLEM 카드뉴스를 못 만드는 진짜 이유

30분~2시간.
카드뉴스 한 세트를 만드는 시간.

2시간
카드뉴스 1세트 제작
소요 시간 (평균)
수만원
외주 맡길 때
건당 비용

1인 브랜드·소상공인에게 이 과정은 구성력 + 카피 + 이미지 + 디자인 툴 숙련도가 모두 필요하다. 결국 "콘텐츠를 만들 시간이 없어서 SNS를 포기하는" 사람이 대부분이다.

INKK의 가설
진짜 장벽은 디자인이 아니라, 'AI 티를 지울 디자인 기술'이 없는 것이다. 그 작업을 서비스 안에 내장하면, 보통 사람도 1분 안에 AI 지문 없는 완성 카드를 받을 수 있다.

"ChatGPT로 하면 되잖아"에 대한 답

PROBLEM 01
AI에는 '시각적 지문'이 있다
결과물을 보면 "어떤 AI로 만들었는지"가 보인다. 팔로워는 그 지문을 알아채고 "성의 없이 AI로 돌렸구나"라고 느낀다.
PROBLEM 02
AI 티를 지우려면 결국 디자인 기술이 필요
보통 사람은 거기까지 못 한다. 편집 능력이 없으니 AI가 뱉은 그대로 올릴 수밖에 없다.
PROBLEM 03
텍스트가 나와도 '발행물'은 아니다
5~10장 흐름 + 이미지 배치 + 인스타 규격 완성은 여전히 사용자 몫이다.

03 · 기획 고민 무엇을 만들지보다 왜 그렇게 만들지가 더 어려웠다

4가지 결정,
각각에 이유가 있어야 했다.

수익 모델
구독이 아닌 크레딧 — 원가가 사용량에 비례한다. 구독은 헤비유저에서 적자가 나지만, 크레딧은 원가와 매출이 항상 같은 방향으로 움직인다.
UX 방향
자유 편집이 아닌 프리셋 — 자유도를 주면 다시 디자인 노동이 시작된다. 스타일 프리셋으로 고정해 사용자는 무드만 고르면 된다.
AI 구조
단일 LLM이 아닌 추상화 — 비용·품질 레버를 코드에 고정하지 않는다. 상황에 따라 런타임에서 전환할 수 있어야 한다.
개발 범위
기능 최대화가 아닌 빠른 검증 — 완성이 아니라 '쓸 수 있는' 상태가 먼저다. 가설이 맞는지 먼저 보고, 나머지는 이터레이션으로.
기획 원칙
무엇을 안 만들지 결정한 것이 무엇을 만들었는지만큼 중요했다.
만들지 않기로 한 것들
✕
이미지 직접 생성 AI
저작권 리스크 → 무료 이미지 라이브러리로 대체
✕
완전 자유 편집 기능
복잡성 증가 → 프리셋으로 단순화, 사용자 노동 제거
✕
카드 1장 재생성
비용·효용 분석 → 수동 편집이 이미 커버, 남은 병목은 유입

경쟁 상대는 캔바가 아니라 '오늘 콘텐츠를 그냥 안 올리는 선택'이다. 좁고 뾰족하게, 그 한 가지 병목만 제거한다.

05 · 도전과 해결 실제로 막혔던 지점 — 그리고 어떻게 풀었나

결제 코드는 "되는 것"과 "동시성·재시도에도 되는 것"이 전혀 다른 문제다.

RESOLVED · 01

Google 로그인 — 자격증명이 맞는데 안 됨

증상: 동의 화면은 뜨지만 인증 완료 단계에서 계속 실패. 자격증명·설정을 전부 점검했지만 이상이 없었다.

결국 인증 코드 교환 흐름에 구조적 불일치가 있었다. 원인을 찾는 데 시간을 쏟기보다 실패하는 경로 자체를 제거하는 방법이 있는지 봤다.
해결: Google One Tap 방식으로 전환 → 실패하던 교환 단계 자체가 사라져 에러가 발생할 수 없게 됨.
RESOLVED · 02

결제 중복 — 보이지 않는 돈 새는 구멍

증상: Stripe webhook은 같은 이벤트를 여러 번 보낼 수 있다. 중복 처리되면 크레딧이 두 배 적립된다.

3라운드에 걸쳐 수정 — 고칠 때마다 새로운 엣지 케이스가 드러났다. 한 번에 완성되는 결제 로직은 없다.
해결: DB 레벨에서 중복 처리를 원천 차단하는 구조로 재설계. 내가 작성한 코드도 반드시 검증 대상이다.
RESOLVED · 03

배포가 조용히 깨져 있었음

증상: 코드를 고쳐 푸시했는데 프로덕션에 반영이 안 됐다. 로컬에선 멀쩡.

Vercel은 빌드 실패 시 직전 성공 버전을 서빙하므로 "배포했는데 안 바뀜"이라는 착시가 생겼다. 빌드 실패를 사람이 확인하는 구조 자체가 병목이었다.
해결: 원인을 수정하고, GitHub Actions에 빌드 게이트를 추가해 재발 방지. "배포했는데 안 바뀐다"는 거의 항상 빌드 실패다.
