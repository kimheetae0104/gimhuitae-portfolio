01 — 문제 정의

결과물은 나온다. "내가 원하는 톤"은 안 나온다.

ChatGPT도 이제 캐러셀 카드뉴스를 만든다. 하지만 폰트·여백·강조·흐름이 일관되게 잡힌 "발행 가능한 결과"를 받으려면 결국 디자인 지식이 필요하다.

Problem 01

결과의 일관성이 들쭉날쭉

같은 주제라도 매번 톤·구성이 달라진다. 만족스러운 결과가 나올 때까지 다시 돌리거나, 손으로 다듬어야 한다.

Problem 02

일관성을 잡으려면 디자인 지식 필요

폰트 크기 · 강조 키워드 · 줄바꿈 · 카드 간 흐름. 결국 디자인을 아는 사람만 "발행 가능한" 결과까지 끌어올린다.

INKK의 가설

일반 사용자가 막히는 지점은 "AI가 못 만들어서"가 아니라 일관성을 잡는 디자인 기술이 없어서다. 그 기술을 서비스 안에 내장하면, 누가 써도 발행 가능한 결과가 처음부터 나온다.

02 — 제품 결정

발행 속도를 판다. 고민할 거리부터 제거.

경쟁 상대는 캔바가 아니라 "오늘 그냥 안 올리는 선택"이다. 그래서 예쁜 편집 자유도 대신 발행 속도에 모든 결정을 걸었다.

01
입력은 주제 한 줄. 길이에 따라 카드 수(5–10장)를 자동 추천해 사용자가 고민할 지점을 없앴다.
02
디자인은 선택이 아니라 프리셋. 색·타이포·여백이 한 세트로 묶인 검증된 스타일 6종 — 무드만 고른다.
03
첫 장은 훅 패턴으로 별도 강제. 통계·숫자·권위·질문 등 훅 패턴을 프롬프트 변수로 빼, 커버 카피를 의도적으로 세게 만든다.
04
Before/After로 가치를 즉시 증명. "같은 주제·같은 시간"을 밋밋한 슬라이드 vs INKK 카드로 나란히 보여준다.

03 — 기술 딥다이브 · 품질 엔진

품질을 운에 맡기지 않는 4층 방어.

AI 카드뉴스의 흔한 실패는 '틀린 결과'가 아니라 '맞지만 밋밋한 결과'다. 문법은 멀쩡한데 아무도 저장하지 않는 카드. 그래서 품질을 4개 층에서 강제했다.

01

장별 역할 분리 프롬프트

"카드뉴스 만들어줘"는 평행 슬라이드를 만든다. 장마다 다른 지시를 받게 갈랐다 — 커버는 스크롤을 멈추는 훅, 본문은 핵심 사실 1문장 + 수치, 마지막은 저장·공유 유도. 장마다 다른 역할을 받으면 기승전결 흐름이 생긴다.

02

GOOD / BAD 반례로 '밋밋함' 차단

LLM은 "좋은 카피를 써라"보다 구체적 반례에 훨씬 잘 반응한다. 밋밋한 출력 패턴을 프롬프트에 미리 박았다.

BAD: "시장에서의 위치를 확인할 수 있습니다." // 공허함 BAD: ["전문가 의견 참고", "시장 위치 파악"] // 공허함 GOOD: "원장이 **숨기는** 1가지"
03

100점 감점식 품질 점수 — QUALITY_PASS_SCORE = 74

LLM 출력을 그대로 믿지 않고 휴리스틱 평가를 통과해야 사용자에게 나간다. 통과 못 하면 사유와 함께 자동 재생성.

  • 헤딩 길이 6–26자 외 감점, 본문 18자 미만 감점
  • 일본어 문자 누출 · 한자 노출 감점 (한국어 LLM 응답 오염 방어)
  • 추상 키워드 사용(중요/필요/도움/팁 등) 감점
  • 본문 카드에 수치 부재 감점, 마지막 카드 CTA 키워드 누락 감점
04

레이아웃 엔진 + sanitize — LLM 출력은 불신

텍스트 길이를 측정해 폰트·행간·레이아웃 타입을 자동 매핑한다. 길이 편차에 무관하게 카드 비율이 항상 균형 잡힌다.

function getFontSize(text) { const len = text.length if (len <= 30) return 48 if (len <= 60) return 36 if (len <= 120) return 28 return 22 }
  • 슬롯 정규화 · LLM이 이미지 슬롯 수를 틀려도 마지막 슬롯 복제 또는 slice로 보정
  • sanitize 하드 트렁케이트 · heading 45자 · body 200자 · tip 50자, 느낌표는 마침표로 일괄 치환
  • 레이아웃 9종 · text-only / top-image / full-bleed / split-2 / grid-2x2 / overlay-caption 등 텍스트 비율에 따라 자동 선택
핵심 철학

퀄리티는 "좋은 프롬프트 한 방"이 아니라 여러 층의 강제 장치가 누적된 결과다. 프롬프트가 80%를 잡고, 점수·sanitize·레이아웃이 나머지 20%의 들쭉날쭉함을 메운다.

04 — 아키텍처 · 보안

돈이 걸린 서비스, 동시성·멱등성부터.

크레딧이 곧 현금이라, 기능보다 "동시 요청·재시도에도 잔액이 안 깨지는가"가 먼저였다. 보안 감사 라운드에서 권한 회수 결함까지 찾아 정리했다.

DB

크레딧 차감을 RPC로 원자화

잔액이 곧 현금이라, 동시 요청이 들어와도 음수가 되지 않도록 차감을 DB 트랜잭션 안에서 처리.

  • 행 잠금 · SELECT FOR UPDATE로 잔액 row를 잠근 뒤 확인·차감
  • SECURITY DEFINER 함수 · 클라이언트는 RPC 한 번만 호출, 잔액 직접 update 불가
  • 실패 시 자동 환불 · LLM 호출 실패하면 refund_credit()가 balance만 +1 (총 구매 수치는 보존)
결제

Stripe webhook 멱등 — 3-state 머신 + 90초 stale 복구

Stripe는 at-least-once 전송이라 같은 이벤트가 여러 번 온다. stripe_events 테이블에 status ∈ ('pending','completed','failed') + claimed_at을 두고, claim_stripe_event RPC로 한 번만 처리되게 강제.

  • 중복 처리 방어 · INSERT ON CONFLICT DO NOTHING으로 신규 row만 클레임 획득
  • 재시도 복구 · failed이거나 pending인 채 90초가 지난 row는 재클레임 가능 (크래시 후 영원히 잠긴 row 방지)
  • try/finally 보장 · 어떤 예외 경로에도 status가 complete 또는 fail로 마킹
보안

CSRF · SSRF · CSP · RLS — 4종 동시 적용

  • CSRF · 모든 변경 API 첫 줄에서 Origin/Referer를 inkk.online 화이트리스트로 검증, 둘 다 없으면 거부
  • SSRF · 이미지 프록시는 호스트 화이트리스트(picsum · unsplash · pexels) + DNS 조회 후 사설 IP·메타데이터 대역 차단 (DNS rebinding 방어)
  • CSP · default-src 'self' · frame-ancestors 'none' · HSTS preload, dev에서만 unsafe-eval
  • RLS · 모든 사용자 데이터 테이블 auth.uid() = user_id, revoke ... from public으로 함수 권한 회수
  • 감사 결과 · decrement_usage를 클라이언트가 호출해 무료 한도를 임의로 리셋할 수 있던 권한 결함을 발견, service role 전용으로 회수

05 — 출시 이후 · 운영

고치기 전에 측정한다.

제품이 도는 것과 사업이 되는 것은 다르다. 출시 후엔 기능을 더 쌓는 대신 "왜 안 쓰는지 보이게" 만드는 일에 집중했다.

측정을 먼저

최적화보다 퍼널 이벤트 로깅 · 관리자 대시보드 · anon_id 쿠키로 가입 전후 잇기를 먼저 깔았다. 측정 없는 최적화는 다음 달에 또 감으로 결정하게 만든다.

무료 깔때기 재설계

초기 "평생 2회"는 가치를 느끼기도 전에 결제 벽에 부딪혔다. 7일 체험 + 월 5회 무료로 바꾸고, 결제가 막는 걸 '생성 횟수'가 아니라 '발행 가능 상태(워터마크 해제)'로 옮겼다 — 습관이 먼저, 결제는 그다음.

API 응답 약 6배 개선

"느리다"를 측정부터. 원인은 DB 지역이 아니라 Vercel 함수가 미국(iad1)이라 태평양을 왕복한 것. vercel.json에 regions:["icn1"] 한 줄로 /api/credits 0.4s → 0.06s. 비싼 마이그레이션 전에 가설을 데이터로 교정했다.

안 만들기로 한 결정

'카드 1장 재생성' 기능은 원가가 새 덱과 비슷했고 수동 편집이 이미 그 needs를 커버해 만들지 않기로 했다. 남은 진짜 병목은 코드가 아니라 유입.
