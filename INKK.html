핵심 기술 01

LLM 출력 일관성 보장 파이프라인

같은 입력에도 LLM 출력이 매번 달라지는 문제를 4단 평가 시스템으로 해결했다. 장별 역할 분리 프롬프트 → 휴리스틱 점수 평가(임계값 미달 시 자동 재생성) → 후처리 sanitize → 글 길이 기반 레이아웃 자동 매핑. 프롬프트 엔지니어링과 후처리 검증을 분리해 한 단계 실패가 전체 품질로 번지지 않게 설계했다.

핵심 기술 02

LLM 평가·재생성 자동화 시스템

LLM 출력을 그대로 사용자에게 보내지 않고 휴리스틱 점수 평가를 통과해야 발행. 임계값 미달이면 사유와 함께 자동 재호출(max retry 캡)하고, 통과 후엔 후처리 sanitize와 글 길이 기반 레이아웃 자동 매핑까지 한 흐름으로 처리한다. 프롬프트 한 방 의존을 제거해 결과 품질의 분산을 줄인 설계.

왜 INKK인가

ChatGPT로도 카드뉴스는 나온다.
발행 가능한 톤까지는 나오지 않을 뿐.

글은 그럴듯하게 나오지만, 5장 흐름·폰트·강조 위치가 매번 다르다. 결국 캔바를 열어 손으로 다듬어야 한다.

일반 사용자는 그 단계에서 막힌다. INKK는 그 다듬는 과정을 서비스가 대신 처리한다.

어떻게 동작하나

붙여넣으면, 카드뉴스가 된다.

주제 한 줄 또는 긴 글을 붙여넣으면 카드 수·스타일·레이아웃까지 자동으로 잡힌다.
사용자는 무드만 고르고 결과를 다듬는다.

품질 파이프라인

긴 글 → 4단계 검증 → 5장 카드뉴스

LLM에 같은 글을 5번 넣으면 5번 다 다른 결과가 나온다. 입력부터 결과까지 4단계 검증을 거치는 파이프라인으로 일관 품질을 강제한다.

LLM 시스템의 품질 · 비용 · 보안 설계

LLM의 비결정성·비용·외부 의존성을 다루면서 내린 세 가지 시스템 설계 결정.

LLM 품질 시스템

프롬프트 한 방 의존 제거 → 4단 평가 파이프라인

LLM 출력의 비결정성을 점수 기반 평가 + 자동 재생성 + 후처리 검증으로 흡수.

  • 역할 분리 프롬프트 · 장별 system prompt + few-shot 반례로 평행 슬라이드 차단
  • 휴리스틱 평가 · 형식·임팩트·CTA 항목별 점수 → 임계값 미달 시 사유와 함께 재호출 (max retry 캡)
  • 결정론적 후처리 · sanitize 트렁케이트 + 길이 기반 레이아웃 자동 매핑으로 LLM 출력 길이 편차 흡수

개발하면서 배운 것

감으로 결정하지 않으려고 측정부터 깔았다

아직 사용자 데이터가 적은 단계라, 트래픽이 본격적으로 들어오기 전에 측정 인프라부터 준비했다.

의심 말고 측정부터

병목은 DB가 아니라 함수 지역이었다

  • API 응답이 느려서 처음엔 DB를 의심
  • 측정해 보니 서버리스 함수가 미국 지역에 있어 태평양 왕복
  • 함수 지역을 서울로 옮기는 한 줄 변경으로 응답 수 배 단축
만들지 않기로 한 결정

'카드 1장만 다시 만들기'는 빼기

  • 한 장만 재생성해도 LLM 호출 비용이 새 덱과 거의 같음
  • 수동 편집으로 같은 결과를 낼 수 있음
  • 우선순위를 코드보다 유입 채널에 두기로 결정
