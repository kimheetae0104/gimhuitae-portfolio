1인 브랜드·소상공인에게 이 과정은 구성력 + 카피 + 이미지 + 디자인 툴 숙련도가 모두 필요하다. 결국 "콘텐츠를 만들 시간이 없어서 SNS를 포기하는" 사람이 대부분이다.

INKK의 가설
진짜 장벽은 디자인이 아니라, 'AI 티를 지울 디자인 기술'이 없는 것이다. 그 작업을 서비스 안에 내장하면, 보통 사람도 1분 안에 AI 지문 없는 완성 카드를 받을 수 있다.

"ChatGPT로 하면 되잖아"에 대한 답

PROBLEM 01
AI에는 '시각적 지문'이 있다
결과물을 보면 "어떤 AI로 만들었는지"가 보인다. 팔로워는 그 지문을 알아채고 "성의 없이 AI로 돌렸구나"라고 느낀다.
PROBLEM 02
AI 티를 지우려면 결국 디자인 기술이 필요
보통 사람은 거기까지 못 한다. 편집 능력이 없으니 AI가 뱉은 그대로 올릴 수밖에 없다.
PROBLEM 03
텍스트가 나와도 '발행물'은 아니다
5~10장 흐름 + 이미지 배치 + 인스타 규격 완성은 여전히 사용자 몫이다.

06 · CHALLENGES 병목과 해결 — 실제로 막혔던 지점

결제 코드는 "되는 것"과 "동시성·재시도에도 되는 것"이 전혀 다른 문제다.

RESOLVED · 01

Google OAuth — 콜백이 끝까지 안 됨

증상: Google 동의 화면은 뜨지만 콜백에서 계속 실패. invalid_client → Unable to exchange external code.

자격증명·리다이렉트 URI·승인 도메인까지 전부 점검했지만 이상 없었다. 결국 문제는 PKCE code verifier와 서버 콜백 라우트 간 매칭이 깨지는 흐름 자체였다.
해결: 서버 코드 교환 방식 대신 Google One Tap ID Token 방식으로 전환 → 실패하던 교환 단계 자체가 사라져 에러가 발생할 수 없게 됨.
RESOLVED · 02

결제 멱등성 — 보이지 않는 돈 새는 구멍

증상: Stripe webhook은 at-least-once 전송. 같은 이벤트가 두 번 오면 크레딧이 두 배 적립.

3라운드에 걸쳐 수정: 1차 중복 차단 → 2차 race condition 발견 → 3차 DB 함수 타입 버그 발견.
해결: DB 레벨 멱등 클레임 패턴 도입. status 컬럼 + stale 자동 복구 타임아웃. 직접 짠 SQL도 반드시 검증 대상이다.
RESOLVED · 03

배포가 조용히 깨져 있었음 — 빌드 실패가 가려진 병목

증상: 코드를 고쳐 푸시했는데 프로덕션에 반영이 안 됐다. 로컬에선 멀쩡.

Vercel은 빌드 실패 시 직전 성공 버전을 서빙하므로 "배포했는데 안 바뀜"이라는 착시가 생겼다. 원인은 useSearchParams()를 Suspense 경계 없이 사용한 것.
해결: <Suspense>로 감싸고, GitHub Actions에 lint + typecheck + test + build 게이트 추가. "배포했는데 안 바뀐다"는 거의 항상 빌드 실패다.
RESOLVED · 04

Vitest 워크트리 테스트 중복 수집

증상: git worktree 작업 중 Vitest가 .claude/ 안 복제 테스트까지 수집해 같은 테스트가 두 번 실행. ESLint도 4만 개 가짜 경고.
해결: vitest.config.ts + eslint.config.mjs에 .claude/** exclude 추가. 도구 설정의 ignore 범위는 작업 환경이 바뀌면 같이 점검해야 한다.
RESOLVED · 05

랜딩 카드 rotate → overflow 잘림

증상: Before/After 카드를 ±10° 회전 배치했더니 모서리가 overflow-hidden에 잘림. 카드 높이만 계산하고 회전 후 실제 점유 영역을 고려하지 않음.
해결: H + (W·sinθ) 계산해 컨테이너 높이 360→420. 회전 카드의 실제 세로 점유 공간을 수식으로 반영해 재배치.
