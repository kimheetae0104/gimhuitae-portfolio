핵심 기술 01

일관된 카드뉴스 자동 생성

같은 글을 AI에 넣어도 결과가 매번 달라지는 문제를 해결했다. 카드 장마다 역할(첫 장은 훅, 본문은 근거, 마지막은 저장 유도)을 따로 지시하고, 결과를 점수로 검증해 부족하면 다시 만든다. 글 길이에 맞춰 5가지 레이아웃 중 하나를 자동으로 골라 카드 비율을 균형 있게 맞췄다.

핵심 기술 02

크레딧 결제·차감 정합성 보장

크레딧이 곧 돈이라 동시에 여러 번 결제 버튼을 눌러도 잔액이 꼬이지 않아야 했다. 잔액을 잠근 뒤 차감하는 방식으로 음수 잔액을 막았고, 결제 알림이 중복으로 들어와도 충전은 한 번만 되도록 처리했다. 차감 후 카드 생성이 실패하면 자동으로 환불된다.

왜 INKK인가

결과는 나온다. 발행할 수준까지 다듬기가 어렵다.

ChatGPT로 카드뉴스를 직접 만들어 봤다. 글은 그럴듯하게 나오지만 5장 흐름·폰트 크기·강조 위치가 매번 다르게 나와서, 그대로 인스타에 올리기엔 어색했다. 결국 캔바를 열어 손으로 다듬었다. INKK는 그 과정을 서비스가 대신 처리하게 만든 도구다.

문제 01

같은 주제도 매번 다르게 나온다

같은 글을 5번 돌리면 5번 다 톤·카드 수·강조 위치가 달라진다. 마음에 드는 결과가 나올 때까지 반복하거나, 받은 결과를 직접 다시 손봐야 한다.

문제 02

다듬으려면 디자인 지식이 필요하다

폰트 크기·강조 키워드·줄바꿈·5장 흐름까지 손보려면 캔바·피그마 같은 도구 사용법과 기본적인 타이포 감각이 있어야 한다. 일반 사용자는 그 지점에서 멈춘다.

어떻게 풀었나

결정할 지점을 최소 4번까지 줄였다.

기존 카드뉴스 도구는 사용자가 카드 수·레이아웃·색·서체·이미지를 다 골라야 한다. INKK는 그 결정 지점을 줄여 입력부터 발행까지 사용자가 누르는 횟수를 최소화하는 쪽으로 설계했다.

01
주제 한 줄만 입력. 글 길이를 분석해 5~10장 사이로 카드 수를 자동 결정. 사용자는 카드 수를 직접 고르지 않는다.
02
스타일 프리셋 6종. 색·서체·여백·이미지 톤을 묶어 만든 6가지 무드 중 하나만 선택. 세부 디자인 옵션은 노출하지 않는다.
03
첫 장 카피 패턴 분리. 훅 패턴(통계·수치·질문·권위 인용)을 프롬프트 변수로 빼서, 커버 카피만 따로 강한 패턴이 적용되게 했다.
04
Before/After 랜딩. 같은 주제를 일반 슬라이드와 INKK 카드로 나란히 보여주는 비교 영역을 랜딩 상단에 배치.

품질을 어떻게 강제했나

AI 결과의 들쭉날쭉함을 4단계로 잡는다.

LLM에 같은 글을 5번 넣으면 5번 다 다른 결과가 나온다. 일관된 품질을 만들려고 프롬프트 한 번에 맡기지 않고, 입력부터 결과까지 4단계 검증을 거치는 파이프라인을 만들었다. 검증을 통과하지 못하면 자동으로 다시 생성한다.

베타 준비 · 결정

데이터가 쌓이기 전에 측정부터 준비해 둔다.

베타 초기라 사용자 데이터는 아직 많지 않다. 그래서 본격적인 트래픽이 들어오기 전에 가입 → 생성 시도 → 카드 다운로드 단계별 이벤트 로깅과 관리자 대시보드를 먼저 깔아 뒀다. 다음에 무엇을 만들지가 감이 아니라 데이터에서 나오도록.

의심 말고 측정부터

API 응답이 느려서 처음엔 DB 문제라고 생각했다. 직접 측정해 보니 서버리스 함수가 미국 지역에 있어 한국에서 호출할 때마다 태평양을 한 번씩 왕복하고 있었다. 함수 지역을 서울로 옮기는 한 줄 변경만으로 응답이 수 배 빨라졌다. 큰 마이그레이션을 데이터로 미리 피했다.

만들지 않기로 한 결정

'카드 1장만 다시 만들기' 기능을 만들지 검토했다. 한 장만 재생성해도 LLM 호출 단가가 새 덱 5장 생성과 거의 같았고, 사용자는 이미 수동 편집(텍스트 수정·이미지 교체)으로 같은 결과를 만들 수 있었다. 만들지 않는 쪽을 선택했다. 우선순위를 코드보다 유입 채널에 두기 위해서.
