핵심 기술 01

일관된 카드뉴스 자동 생성

같은 글을 AI에 넣어도 결과가 매번 달라지는 문제를 해결했다. 카드 장마다 역할(첫 장은 훅, 본문은 근거, 마지막은 저장 유도)을 따로 지시하고, 결과를 점수로 검증해 부족하면 다시 만든다. 글 길이에 맞춰 레이아웃까지 자동으로 골라 카드 비율을 균형 있게 맞췄다.

핵심 기술 02

크레딧 결제·차감 정합성

크레딧이 곧 돈이라 동시에 여러 번 결제 버튼을 눌러도 잔액이 꼬이지 않아야 했다. 잔액을 잠근 뒤 차감하고, 결제 알림이 중복으로 들어와도 충전은 한 번만 되도록 처리했다. 차감 후 카드 생성이 실패하면 자동으로 환불된다.

왜 INKK인가

ChatGPT로도 카드뉴스는 나온다.
발행 가능한 톤까지는 나오지 않을 뿐.

글은 그럴듯하게 나오지만, 5장 흐름·폰트·강조 위치가 매번 다르다. 결국 캔바를 열어 손으로 다듬어야 한다.

일반 사용자는 그 단계에서 막힌다. INKK는 그 다듬는 과정을 서비스가 대신 처리한다.

어떻게 동작하나

붙여넣으면, 카드뉴스가 된다.

주제 한 줄 또는 긴 글을 붙여넣으면 카드 수·스타일·레이아웃까지 자동으로 잡힌다.
사용자는 무드만 고르고 결과를 다듬는다.

01
입력
주제 한 줄 또는 긴 원문 전체를 그대로 붙여넣기
02
생성
장별 역할 분리 프롬프트로 5~10장 카드 자동 생성
03
조정
글 길이에 맞춰 폰트·여백·레이아웃 자동 매핑

품질을 어떻게 잡나

검증을 통과해야 사용자에게 나간다.

AI 출력 그대로 보내지 않는다. 점수 평가를 통과해야 발행 가능한 결과로 인정한다.

LLM에 같은 글을 5번 넣으면 5번 다 다른 결과가 나온다.
일관된 품질을 만들려고 입력부터 결과까지 4단계 검증을 거치는 파이프라인을 만들었다.

통과 못 한 결과는 사유와 함께 다시 생성한다.
한 단계가 놓친 것을 다음 단계가 잡아낸다.

생성 파이프라인

긴 글 → 4단계 검증 → 5장 카드뉴스

4단계
품질 검증 — 역할 분리 · 반례 · 점수 · 레이아웃
5종
레이아웃 자동 매핑 — 풀블리드/상하/좌우/그리드/오버레이
6개
스타일 프리셋 — 무드만 선택
01 · 역할 분리 프롬프트

장마다 다른 지시

  • 커버는 스크롤을 멈추는 훅 카피
  • 본문은 핵심 사실 + 수치
  • 마지막은 저장·공유 유도
프롬프트기승전결
02 · 반례 차단

밋밋한 표현은 미리 제외

  • 흔히 나오는 추상 표현을 프롬프트에 반례로 박음
  • 강한 카피 패턴은 예시로 같이 제시
Few-shot반례 학습
03 · 점수 평가

통과 못 하면 자동 재생성

  • 헤딩 길이·언어 오염·수치 부재 등 형식 검증
  • 임팩트 부족·CTA 누락 항목 감점
  • 임계값 미만이면 사유와 함께 재생성
휴리스틱재생성
04 · 레이아웃 매핑

글 길이에 맞춰 자동 선택

  • 풀블리드 · 상하 2중 · 좌우 2중 · 4중 그리드 · 오버레이
  • 5가지 레이아웃 중 자동 선택
  • 카드 비율을 항상 균형 있게 유지
자동 매핑5종 레이아웃

엔지니어링 디테일

돈이 걸린 코드의 신뢰성

결제·잔액·LLM 비용처럼 돈이 직접 걸린 코드를 만들면서 내린 결정들.

잔액 동시성

크레딧 차감을 DB 안에서 원자 처리

크레딧이 곧 돈이라, 동시에 여러 번 결제를 눌러도 잔액이 꼬이지 않아야 했다.

  • 행 잠금 차감 · 잔액을 잠근 뒤 확인·차감해 동시 요청에도 음수로 깨지지 않음
  • 권한 분리 · 클라이언트는 잔액에 직접 접근하지 못하고 서버 함수만 호출
  • 실패 시 자동 환불 · LLM 호출이 실패하면 잔액 복구 (총 구매 이력은 유지)
결제 멱등성

같은 결제 알림이 여러 번 와도 충전은 한 번만

결제 알림은 같은 이벤트가 여러 번 들어올 수 있어, 한 번만 처리되도록 강제했다.

  • 중복 차단 · 이미 처리한 이벤트는 즉시 무시
  • 재시도 복구 · 처리 중 크래시가 나도 일정 시간 후 자동 재시도 (영원히 잠긴 row 방지)
  • 상태 보장 · 어떤 예외 경로에도 처리 결과(성공·실패)가 명확히 기록
품질 다층 방어

AI 출력을 그대로 사용자에게 보내지 않는다

같은 글을 5번 넣으면 5번 다 다른 결과가 나오는 LLM 특성에 대응.

  • 4단 검증 · 역할 분리 프롬프트 → 반례 차단 → 점수 평가 → 레이아웃 자동 매핑
  • 자동 재생성 · 점수 미달이면 사유와 함께 재호출
  • 한 단계가 놓친 것을 다음 단계가 잡아냄
보안·비용 가드

변경 API · 이미지 프록시 · LLM 비용 다층 차단

결제가 걸린 서비스라 보안 기본기와 비용 가드를 다층으로.

  • 변경 API · 출처 검증으로 외부 사이트의 위변조 요청 차단
  • 이미지 프록시 · 허용된 호스트만 통과, 내부망 접근 차단
  • 비용 가드 · 운영 키 부재 시 안전 모드로 자동 폴백 (무한 비용 차단)

개발하면서 배운 것

감으로 결정하지 않으려고 측정부터 깔았다

아직 사용자 데이터가 적은 단계라, 트래픽이 본격적으로 들어오기 전에 측정 인프라부터 준비했다.

의심 말고 측정부터

병목은 DB가 아니라 함수 지역이었다

  • API 응답이 느려서 처음엔 DB를 의심
  • 측정해 보니 서버리스 함수가 미국 지역에 있어 태평양 왕복
  • 함수 지역을 서울로 옮기는 한 줄 변경으로 응답 수 배 단축
만들지 않기로 한 결정

'카드 1장만 다시 만들기'는 빼기

  • 한 장만 재생성해도 LLM 호출 비용이 새 덱과 거의 같음
  • 수동 편집으로 같은 결과를 낼 수 있음
  • 우선순위를 코드보다 유입 채널에 두기로 결정
