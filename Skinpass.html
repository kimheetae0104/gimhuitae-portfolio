03 · PROBLEM 왜 중요한가
코일 10개 중 4개는 소둔 후에 예외 공정으로 빠진다.
그중 60%는 소둔 투입 전에 포착된다.

비계획 Skinpass는 소둔이 끝난 뒤 품질 기준을 못 맞춘 코일에 긴급 투입되는 예외 공정이다. 설비 가동률, 납기, 에너지, 물류 비용에 모두 영향을 준다. 소재 입고 시점 데이터만으로 이 40.8%를 미리 걸러낼 수 있다면 운영 방식 자체가 달라진다.

05 · 가설 검증 4 ACCEPTED

가설 4개를 먼저 세우고 통계로 바로 검증했다.

H1 · 재질등급
재질등급 C가 발생률을 구조적으로 높이는가?
✓ Kruskal-Wallis p < 0.001
→ Material Gate 진입 조건으로 직접 활용
H2 · 항복강도
항복강도 임계값이 비계획 위험을 가르는가?
✓ Mann-Whitney p < 0.001
→ Material Gate와 quality_risk_score 설계에 반영
H3 · 형상·표면 복합
형상과 표면 조건이 함께 나쁠 때 위험이 더 커지는가?
✓ Kruskal-Wallis p < 0.001
→ surface_shape_composite 파생변수 생성
H4 · 강종 × 등급
강종과 재질등급 조합이 위험 패턴을 구조적으로 바꾸는가?
✓ Kruskal-Wallis p < 0.001
→ grade_steel_interaction 파생변수 생성
가설 검증 결과 시각화 (H1~H4)

H1~H4는 모두 파생변수와 Gate 조건으로 직접 연결했다. SHAP 분석에서 이 가설 기반 변수들이 상위권에 올라, 처음 세운 도메인 가설이 모델에서도 그대로 작동한다는 걸 확인했다.

06 · ARCHITECTURE 2단계 의사결정

현장에서 코일을 판단하는 순서를 그대로 모델에 옮겼다.

STAGE 1 · MATERIAL QUALITY GATE

명백한 고위험은 규칙으로 먼저 걸렀다

IF 재질등급 == C
OR 항복강도 ≥ 임계값
→ 고위험 분류 (Gate=1)
H1 + H2 검증 결과를 그대로 묶은 하드 필터다. Gate=1이면 담당자가 먼저 확인한다.
STAGE 2 · LOGISTIC REGRESSION

애매한 구간은 확률로 다시 판단했다

quality_risk_score · process_risk_composite
surface_shape_composite · grade_steel_interaction
두께/폭 비율 · 시간×온도 상호작용
H2·H3 기반 복합 파생변수가 상위권에 올라, 도메인 가설이 모델 안에서도 유지됐다.
Gate 발동별 비계획 발생률 · Recall-Precision 트레이드오프

08 · RESULTS Recall을 우선했다
Final Decision

최종 선택은 Gate + LR이었다.

비계획 발생을 놓치면(FN) 긴급 공정 투입 비용이 생기고, 오탐(FP)은 예방적 대응으로 끝난다. 그래서 Recall을 1순위로 뒀고, 이 기준이 최종 모델 선택을 결정했다.

복잡한 모델보다 미탐지를 가장 덜 내는 구조가 이 문제에 더 맞았다.
6개 모델 성능 비교
MODEL RECALL F1 AUROC FN
★ Gate + LR (최종) 0.595 0.494 0.581 163
Logistic Regression 0.531 0.495 0.581 187
LightGBM 0.408 0.427 0.565 237
SVM (RBF) 0.435 0.451 0.573 226
Random Forest 0.392 0.418 0.571 243
Decision Tree 0.370 0.395 0.535 252
왜 LightGBM이 아니라 LR + Gate인가
LightGBM은 F1·AUROC는 비슷하지만 Recall이 0.408로 낮았다. 미탐지를 줄이는 게 목표라면 LR이 더 적합했고, 계수 부호로 위험 방향을 설명할 수 있다는 점도 강점이었다.
가설 기반 변수가 실제로 상위권에 올랐다
SHAP이 다시 확인한 것
①
가설 기반 파생변수가 최상위권을 차지했다.
②
항복강도는 원천 변수 중 가장 강한 신호였다.
③
강종 × 등급 조합도 상위권에 올라 H4와 맞아떨어졌다.

09 · 한계점 & 인사이트 한계와 배운 점
현재 모델의 한계
⚠
핵심 변수 미수집소둔로 내부 조건(분위기 가스 성분, 위치별 온도 분포)이 없어 AUROC가 0.55~0.59 수준에서 멈췄다. 상업 배포 수준(≥0.7)에는 못 미쳤다.
⚠
레이블 노이즈비계획 발생 레이블이 검사자의 주관적 판단에 의존했다. 객관적 수치 기준이 없으면 학습 품질도 함께 흔들린다.
⚠
시계열 패턴 미반영코일을 독립 관측치로 처리해 생산 순서 드리프트와 계절성이 반영되지 않았다. 다음 단계에서는 시계열 구조를 따로 다뤄야 한다.
⚠
외부 요인 미포함원자재 로트 변화와 설비 노후화 정보가 없어 장기 패턴 변화에 취약하다. 보조 데이터 연계가 필요하다.
이 프로젝트에서 배운 것
가설이 바로 피처가 됐다
도메인 가설을 통계로 검증한 뒤 Gate와 파생변수로 바로 연결했다. SHAP은 그 설계가 맞았다는 사후 검증이 됐다.
문제 정의가 모델 선택보다 먼저였다
핵심은 어떤 알고리즘이 더 센지가 아니라, 소둔 전에 무엇을 판단해야 하는지부터 정리한 데 있었다. 공정 순서를 알아야 입력 변수도 제대로 고를 수 있었다.
지표 선택이 문제 정의다
미탐지 비용이 더 크다는 판단에서 Recall을 1순위로 뒀다. 이 선택이 모델 선택과 임계값 조정 방향을 함께 결정했다.

10 · DEPLOYMENT 적용 단계 3개
이 모델은 완전 자동화보다 위험 가능성이 높은 코일을 먼저 보여주는 방식에 더 적합했다.
그래서 공정을 바로 제어하기보다, 소둔 투입 전에 위험 가능성이 높은 코일을 먼저 표시하고 운영자가 대응 순서를 정하도록 돕는 쪽이 더 현실적이었다.
01
경보 시스템
Gate=1 코일을 소둔 투입 전에 먼저 띄우고, 운영자가 우선 확인하도록 만든다.
고위험 포착 ≥ 80% · 1–2개월
02
의사결정 지원
전 코일에 발생 확률과 주요 원인 3가지를 함께 보여주고, 점검 우선순위를 정하게 한다.
발생률 −10% · 2–4개월
03
반자동 제어
고위험 코일에 대해 소둔 조건 조정안을 먼저 제시하고, 승인 후 반자동으로 실행한다.
발생률 −25% · 4–8개월
