# Blog Agent — 한국 주식 분석 블로그 자동화 (v13)

> 매일 장 마감 후 상한가 종목을 자동 감지·분석·작성·검증·배포하는 무인 LLM 파이프라인

---

## 01. 프로젝트 소개

- **프로젝트 이름**: Blog Agent (한국 주식 분석 블로그 자동 생성·검증·배포 시스템)
- **한 줄 요약**: 매일 장 마감 직후(월~금 15:40) 상한가 종목을 자동 감지하고, 7단 RAG로 사실 데이터를 수집해 환각 없는 SEO 분석 블로그를 작성·검증·배포하는 완전 자동화 시스템
- **현재 버전**: v13 (RAG 7단 + Gemini 무료 검증 + 종목코드 뉴스 + 보안 강화)
- **스케줄**: 월~금 15:40 cron 자동 실행 (장 마감 직후)
- **일일 처리량**: 이슈 점수 기반 자동 선정 최대 3개 종목 → 작성·검증·배포

**GitHub**: https://github.com/kimheetae0104/Agent/tree/blog-agent-pr

## 02. 배경과 목적

### 배경

매일 한국 주식 시장에서 +10% 이상 급등 종목이 5~15개 발생합니다. 종목 하나를 제대로 분석하려면:

- DART에서 재무제표·공시·사업보고서 확인
- 네이버 금융에서 시세·기업개요 확인
- 뉴스 3~5개 읽고 상한가 원인 파악
- 관계회사·지분 시계열 추적
- 1,500자 SEO 분석 글 작성
- 네이버 블로그 + Google Sheets 배포

종목당 **1시간 이상**, 5종목이면 하루의 절반이 사라집니다.

### 핵심 문제 — LLM 환각

단순히 LLM에게 "오늘 상한가 종목 분석 글 작성"을 맡기면:

- 경인전자(전자부품 리모컨 제조사)를 "엔터테인먼트 산업 강점"으로 서술
- 실제 매출 229억원을 "1조원"으로 환각
- 종목코드 009140을 017250으로 잘못 기재
- 영업적자(-13억원) 회사를 "안정적 재무 상태"로 설명

**투자 콘텐츠의 환각은 자본시장법 위반 + 독자 피해로 직결됩니다.**

더 큰 모델(Gemini, Claude)로 교체해도 입력 데이터 없이는 동일한 환각이 반복됐습니다.

### 목적

- **무인 자동화**: 사람 없이 월~금 15:40 자동 실행, 3개 종목 선정·작성·배포
- **환각 차단**: 7단 RAG 데이터 주입 + 5중 검증으로 수치 환각 0건 달성
- **품질 유지**: 정답글 작성자 수준의 인과관계 추적 및 재무 해석 자동화

## 03. 핵심 문제와 해결

### 문제 1 — 데이터 없이 LLM이 채우면 환각

**현상**: 프롬프트에 "사실에 기반해 작성하라"고 지시해도, LLM은 모르는 정보를 확률적으로 생성합니다.

**구체 사례 (경인전자, 009140)**:
```
[v3 시스템 출력]
"엔터테이먼트 산업에서의 강점이 부각됐습니다"  ← 실제: 리모컨 제조업
"2026년 매출 1조원"                           ← 실제: 229억원 (4259% 차이)
"영업이익 6억원, 안정적 재무"                  ← 실제: 영업이익 -13억원(적자)
#017250, #반도체                              ← 실제 코드 009140, 반도체 무관
```

**해결**: **7단 RAG** — 소스별 최적 추출 방식으로 사실 데이터를 명시적으로 주입

| RAG 단계 | 데이터 소스 | 추출 방식 |
|---|---|---|
| 1 | DART 재무 API | JSON 파싱 → 매출/영업이익/순이익 |
| 2 | DART 사업보고서 본문 | 정규식 → 타법인 출자 시계열 지분 추적 |
| 3 | DART 최근 7일 공시 | API → 유상증자/배당 등 핵심 트리거 |
| 4 | 네이버 금융 기업개요 | 크롤링 → 에프앤가이드 한 줄 요약 |
| 5 | 네이버 금융 시세 | 크롤링 → PBR/EPS/PER/시총/52주 |
| 6 | 시장 시황 | 크롤링 → KOSPI/KOSDAQ 인덱스 |
| 7 | Obsidian RAG | 220개 과거 포스트 → nomic-embed-text → chromadb → 섹터 필터 2단계 → 유사 포스트 2개 Few-shot 주입 |

---

### 문제 2 — 프롬프트 가이드로도 모순이 잡히지 않음

**현상**: 시스템 프롬프트에 `PBR 0.49배 = 저평가`라고 명시해도 LLM이 "PBR 0.49배로 **높습니다**"라고 출력합니다.

**해결**: **5중 검증 + 자동 교정**

```
① 형식 검증    → ## 헤딩 4개 / 한글 800자+ / 해시태그 10개+
② 팩트체커     → DART 수치 50%+ 차이 → 환각 판정 → 재시도
③ 모순 감지    → 13+ 룰 (PBR·PER·EPS·적자+안정적·상한가·시장구분·사업분야·재무강점 등)
④ 자동 교정    → MAX_RETRIES=2 후 잔재 → _auto_fix_contradictions() 코드 강제 교정
⑤ Gemini 검증 → gemini-2.5-flash-lite (무료 티어) → 종목혼동/수치환각/밸류에이션모순 score 0~100
```

**핵심 인사이트**: LLM이 못 고치는 잔재는 코드가 결정론적으로 교정합니다. "LLM이 못 한다면 코드가"가 이 시스템의 원칙입니다.

## 04. 내가 한 것 — 액션과 인사이트

### 직접 수행한 액션 5가지

**액션 1 — DART 시계열 지분 추적 정규식 개발**

DART 사업보고서엔 지분 변동이 시간순으로만 기록돼 있습니다:
```
2016.09 고퀄 지분 34.07% 취득 → 2017년 32.77% → 2023년 21.52% (최신)
```
정규식으로 초기 취득부터 모든 후속 변경을 추적해 최신값만 추출하는 파서를 직접 작성했습니다. 정답글 작성자가 가장 중요시하는 "지분 시계열" 정보를 자동 인용하기 위해서입니다.

**액션 2 — 룰베이스 모순 감지 13+ 룰 직접 작성**

PBR/PER/EPS/적자+안정적/상한가/시장구분/사업분야/재무강점 등 한국 주식 분석 특유의 모순 패턴을 직접 코드로 정의했습니다. LLM이 재시도해도 **변형 표현**("재무지표상 안정적 흐름" → "안정적인 재무 상태")으로 같은 모순을 반복하는 현상을 발견해 정규식을 다중 패턴으로 확장했습니다.

**액션 3 — _auto_fix_contradictions() 자동 교정 도입**

LLM 재시도만으로 해결되지 않는 잔재를 코드가 결정론적으로 교정하는 함수를 설계했습니다. 재시도 비용과 불확실성 없이 마지막 안전망 역할을 합니다.

**액션 4 — 매 버전 외부 검토 + 룰 흡수 반복**

v7에서 "환각 0건"이라 자평했으나 외부 검토자가 에이프로젠바이오로직스 글에서 즉시 3가지 오류 발견: 시장 구분 오류(KOSDAQ → 실제 KOSPI), 사업분야 단정, 재무강점 모순. 이를 v12에서 3개 룰로 흡수해 시스템에 반영했습니다.

**액션 5 — Obsidian RAG 인덱서 구축 (v13)**

과거 직접 작성한 220개 .md 파일을 nomic-embed-text 임베딩 + chromadb로 벡터화했습니다. 단순 검색이 아닌 **섹터 필터 2단계** (같은 섹터 우선 → 전체 폴백)로 유사 포스트 2개를 LLM 프롬프트에 주입해 Few-shot 품질을 강화했습니다.

### 핵심 인사이트 3가지

**인사이트 1 — "LLM이 더 똑똑하면 환각 줄어든다"는 가설은 틀림**

Gemini Flash, Claude API까지 시도했지만 입력 데이터 없이는 동일한 환각 패턴이 반복됐습니다. 환각은 모델 크기가 아니라 **입력 데이터 부족**의 문제입니다.

**인사이트 2 — 프롬프트 가이드만으로는 안 잡힌다**

"PBR < 1 = 저평가"를 명시해도 LLM이 무시합니다. 코드 검증·교정이 마지막 안전망입니다.

**인사이트 3 — 자기 측정 지표가 좁으면 자기 합리화에 빠진다**

"수치 환각 0건"이라 자평했는데 외부 검토자가 시장구분·사업분야·평가논리 환각을 즉시 발견했습니다. 측정 기준의 한계 명시가 신뢰의 기반입니다.

## 05. 결과물 — 최종 시스템 (v13)

### 전체 파이프라인 (10단계)

```
[스케줄러] 월~금 15:40 cron 자동 실행
      ↓
1. 상한가 감지 (네이버 금융 크롤링, +10% 이상)
      ↓
2. 이슈 점수 계산
   IssueScore = 거래량(30%) + 뉴스수(40%) + 네이버 검색량(30%)
   30점 미만 스킵 / 직접 관련 뉴스 없으면 스킵 / 최대 3개 선정
      ↓
3. 7단 RAG 데이터 수집
   DART (재무·사업보고서·공시·지분) + 네이버 (기업개요·시세·시황)
   + Obsidian RAG (220개 과거 포스트 벡터 DB, 유사 포스트 2개)
      ↓
4. 뉴스 3소스 병렬 수집
   ① 네이버 검색 (종목명+상한가/급등/주가 3쿼리)
   ② Google News RSS (18개 언론사 화이트리스트)
   ③ 네이버 금융 종목탭 (code={6자리코드}, 동명이종 차단)
      ↓
5. 로컬 LLM 작성 (exaone3.5:7.8b / Ollama)
   AI_MODE=cloud면 gemini-2.5-flash 사용
      ↓
6. 검증 루프 (MAX_RETRIES=2)
   형식 → 팩트체커 → 모순 감지 → 재시도 → 자동 교정
      ↓
7. Gemini 검증 (gemini-2.5-flash-lite, 무료 티어)
   429 쿼터 소진 시 자동 폴백 (4단계 모델 큐)
   score 0~100, critical=True → Telegram 긴급 알림
      ↓
8. 후처리 (메타 라벨 제거, 해시태그 교정, 뉴스 노이즈 정리)
      ↓
9. 다중 배포
   Google Sheets + Obsidian + Telegram + (선택) Naver Blog
      ↓
10. Obsidian RAG 실시간 인덱싱 (배포한 글 → 벡터 DB 반영)
```

### 7단 RAG 상세

| 단계 | 소스 | 내용 | 추출 방식 |
|---|---|---|---|
| 1 | DART 재무 | 매출/영업이익/순이익/부채비율/유보율 | DART OpenAPI JSON |
| 2 | DART 사업보고서 | 사업 내용/주요 고객/지분 시계열 | XML 파싱 + 정규식 |
| 3 | DART 공시 | 최근 7일 유상증자/배당 등 | DART OpenAPI JSON |
| 4 | 네이버 금융 기업개요 | 에프앤가이드 한 줄 요약 | HTML 크롤링 |
| 5 | 네이버 금융 시세 | PBR/EPS/PER/시총/52주 | HTML 크롤링 |
| 6 | 시장 시황 | KOSPI/KOSDAQ 인덱스 + 등락률 | HTML 크롤링 |
| 7 | Obsidian RAG | 220개 과거 포스트 벡터 검색 | chromadb + nomic-embed-text |

### 5중 검증 상세

| 단계 | 방식 | 검출 기준 | 대응 |
|---|---|---|---|
| ① 형식 검증 | 정규식 | ## 헤딩 4개 미만 / 한글 800자 미만 / 해시태그 10개 미만 | 재시도 |
| ② 팩트체커 | DART 수치 대조 | 매출/영업이익/순이익 50%+ 차이 | 재시도 |
| ③ 모순 감지 | 룰베이스 13+ 룰 | PBR·PER·EPS·적자+안정적·상한가·시장구분·사업분야·재무강점 | 재시도 |
| ④ 자동 교정 | 정규식 치환 | MAX_RETRIES=2 후 잔재 | 코드 강제 교정 |
| ⑤ Gemini 검증 | LLM (gemini-2.5-flash-lite) | 종목혼동/수치환각(30%+)/종목코드/사실창작/밸류에이션모순 | critical→배포차단 |

## 07. 역량과 기여

### 느낀 점 + 다짐

> "LLM 응용 시스템에서 '환각 방지'는 모델이 아니라 **시스템 설계**의 문제다. 데이터 입력 → LLM → 검증 → 교정 → 배포까지 완결된 파이프라인을 설계할 수 있어야 한다."

이 프로젝트를 통해 LLM을 단일 모델이 아닌 **시스템의 한 컴포넌트**로 바라보는 관점을 갖게 됐습니다. 검증·교정 레이어를 처음부터 설계에 포함시키는 방식, 외부 검토에서 무너지지 않는 지표를 만드는 태도를 입사 후에도 유지하겠습니다.

> "외부 검토에서 무너지지 않는 지표를 만든다. 자기 측정으로 끝나지 않는다."

v1~v13 GitHub 커밋 로그는 "문제 발견 → 룰 설계 → 코드 반영 → 재측정"을 반복한 실제 기록입니다. 이 사이클을 팀에서도 기여할 수 있습니다.
