# Blog Agent — 한국 주식 분석 블로그 자동화

---

## 01. 프로젝트 소개

- **프로젝트 이름**: Blog Agent (한국 주식 분석 블로그 자동 생성·배포 시스템)
- **프로젝트 특징**: 매일 상한가/급등 종목을 자동 수집해 환각 없는 SEO 분석 블로그를 작성하고 네이버·Google Sheets·Obsidian에 동시 배포하는 **RAG + 환각 방지 시스템**.

---

## 02. 프로젝트 개요 — 배경과 목적

- **배경**: 매일 한국 시장에 +10% 이상 급등 종목이 5~15개 발생. 종목당 시세·DART 공시·뉴스·관계회사 추적·1,500자 SEO 글 작성·다중 채널 배포가 **1시간 이상** 소요. 5종목이면 하루의 절반.

- **목적**: 매일 자동 수집·분석·작성·배포까지 무인 운영하면서, LLM 환각으로 인한 **잘못된 투자 정보(자본시장법 위반·독자 피해)**를 차단하는 것.

---

## 03. 진행한 일 — 배경 / 문제 / 해결

- **배경**: 초기 시도는 Ollama 로컬 LLM에게 "오늘 상한가 종목 분석 글 작성"이라고 통째로 맡김.

- **문제 (핵심)**:
  - LLM이 모르는 정보를 추측으로 채움 → 환각 다발
  - 예: 경인전자(전자부품 리모컨 제조사)를 "엔터테이먼트 산업 강점", "매출 1조원(실제 229억)"으로 거짓 서술
  - 투자 콘텐츠에서 환각은 자본시장법 위반 + 독자 피해 직결
  - **단순 "더 똑똑한 모델로 바꾸기"로 해결 안 됨** (Gemini/Claude도 같은 패턴 환각)

- **해결**: **데이터 파이프라인 보강 + 다층 검증**
  - DART/네이버/뉴스 6개 소스에서 사실을 명시 추출해 LLM 입력으로 주입 (RAG)
  - 형식 검증 + 팩트체커(DART 수치 대조) + 룰베이스 모순 감지 + Self-critique 4중 검증
  - LLM이 못 고친 잔재는 코드가 강제 교정하는 안전망

---

## 04. 과정 — 나의 직접적인 액션 + 인사이트

- **액션**:
  - DART OPEN API에서 사업보고서 본문을 직접 XML 파싱해 "타법인 출자현황 시계열 변동" 정규식 추출 (정답글 작성자가 가장 중요시한 정보)
  - 룰베이스 모순 감지 13+ 룰 직접 작성 (PBR/PER/적자안정/상한가/시장구분/사업분야/재무강점 등)
  - LLM이 재시도해도 같은 모순을 변형 표현으로 반복하는 현상 발견 → 코드 강제 교정 함수 `_auto_fix_contradictions` 도입
  - 매 버전 결과를 외부에 보여주고 검토자가 발견한 새 환각 유형(시장 구분, 사업 분야 단정 등)을 룰로 흡수해 v12까지 반복 개선

- **인사이트**:
  - **"LLM이 더 똑똑하면 환각 줄어든다"는 가설은 틀림**. 환각은 모델 크기가 아니라 **입력 데이터 부족**의 문제. GPT-4도 데이터 없으면 똑같이 환각.
  - **프롬프트 가이드만으로는 안 잡힌다**. LLM에 "PBR < 1 = 저평가" 명시해도 "PBR 0.49배로 높다" 출력. 코드 검증·교정이 마지막 안전망.
  - **자기 측정 지표가 좁으면 자기 합리화에 빠진다**. "환각 0건"이라 자평했는데 외부 검토자가 시장구분·사업분야·평가논리 환각 발견. 측정 기준의 한계 명시 필수.

---

## 05. 결과물 — 최종으로 진행한 내용 + 포인트

- **내용**: 6단 RAG (DART 재무·사업보고서·공시·지분 + 네이버 기업개요·시황) + LLM(Gemini Flash) + 4중 검증(형식/팩트/모순/Self-critique) + 자동 교정 + 다중 배포(Sheets/Naver/Obsidian/Telegram).

- **포인트 1 — 도메인 RAG 설계**: 단순 "벡터 DB + 임베딩" 챗봇 RAG가 아니라, 데이터 소스별로 최적 추출 방식(API/정규식/크롤링) 선택. DART 사업보고서엔 정규식이 임베딩보다 정확.

- **포인트 2 — 시계열 지분 추적**: DART 사업보고서의 "고퀄 지분 34% 취득 → 32% → ... → 21.52%" 시간순 변동에서 최신값만 정규식으로 추출 → 정답글 핵심 트리거를 자동 인용.

- **포인트 3 — 3중 안전망**: 시스템 프롬프트 가이드(1차) → 룰베이스 검증·재시도(2차) → 코드 강제 교정(3차). LLM이 못 고치는 잔재까지 잡음.

- **포인트 4 — 솔직한 메트릭**: "환각 0건"이 아니라 "수치 환각(DART 50%+ 차이) 0건"으로 측정 기준 명시. 의미론적 환각(시장구분·사업분야)은 별도 룰로 v12에서 보강한 과정 자체를 기록.

---

## 06. 성장한 점 — 성과 + 배운점

- **성과**:
  - 환각 (DART 수치 50%+ 차이) **v3 5종목 중 3건 → v12 0건**
  - 의미론적 환각 (외부 검토자 평가) **5종목 중 1건 → v12 룰 보강으로 차단 가능**
  - 작성 시간 **종목당 1시간 → 5종목 자동 30분 (병렬 + 재시도 포함)**
  - GitHub 30+ 의미 있는 커밋, v1~v12 반복 개선 기록 자산화

- **배운점**:
  - **LLM 응용의 본질은 "데이터 파이프라인 설계"**. 모델 교체·프롬프트 튜닝은 데이터 보강 다음 순위.
  - **자기 검증의 한계** — 같은 LLM이 자기 환각 못 잡고, 좁은 자기 측정 기준은 자기 합리화로 흐름. 외부 검토자 + 룰베이스 검증이 필수.
  - **솔직한 한계 명시**가 신뢰의 기반 — 외부 검토에서 한 번에 무너지는 자기 평가는 무의미.

---

## 07. 나의 역량 — 입사 시 기여할 수 있는 부분

- **느낀점 + 다짐**:
  > "LLM 응용 시스템에서 '환각 방지'는 모델이 아니라 **시스템 설계**의 문제다. 데이터 입력 → LLM → 검증 → 교정 → 배포까지 완결된 파이프라인을 설계할 수 있어야 한다."

  앞으로는 LLM을 단일 모델이 아닌 **시스템의 한 컴포넌트**로 보고, 검증·교정 레이어를 처음부터 설계에 포함시키는 방식으로 일하고 싶다.

- **배운점 + 다짐**:
  > "외부 검토에서 무너지지 않는 지표를 만든다. 자기 측정으로 끝나지 않는다."

  매 버전 결과를 외부에 노출해 사각지대를 발견하고, 그 발견을 시스템에 흡수하는 반복 개선 능력을 기여할 수 있다. v1~v12 GitHub 커밋 로그가 이 사이클의 실제 기록.
