# 배운 점 · 시행착오 · 의사결정 기록

포트폴리오에서 가장 중요한 부분 — **무엇을 시도하고, 무엇이 안 되고, 왜 그렇게 결정했는가**.

---

## 시행착오 1: "LLM이 더 똑똑하면 환각 줄까?"

**가설**: 큰 모델을 쓰면 환각이 줄어들 것이다.

**시도**:
- Ollama (exaone3.5 7.8B) → 환각 심각 ("매출 1조원" 등)
- Gemini Pro → 무료 한도 0
- Gemini Flash → 작동, 그런데 같은 환각 패턴
- Claude API → 키 없음

**결론**: **LLM 크기 문제가 아니다.** GPT-4도 "경인전자가 고퀄 지분 21.52%" 데이터를 입력으로 안 주면 똑같이 환각 만든다.

**진짜 해결**: 데이터 파이프라인 보강 (RAG). 입력에 사실이 있으면 어떤 LLM이든 정확히 인용.

---

## 시행착오 2: "Cloud LLM 호출이 안 되는데 글이 어떻게 나오지?"

**현상**: `--cloud` 플래그로 실행했는데 글은 만들어짐. 환각 심함.

**원인 파악**: `.env`에 `ANTHROPIC_API_KEY` 없는 상태에서 `_call_cloud()` 호출 → 인증 실패 → 코드 어딘가에서 silently ollama로 fallback. 사용자는 cloud 쓰는 줄 알고 있었음.

**교훈**: **무엇이 실제로 도는지 검증하는 것이 가장 중요**. 환각 원인 분석할 때 모델 자체를 의심하기 전에 "지금 진짜 무슨 모델이 도는가" 확인.

---

## 시행착오 3: "분량을 강제하면 더 좋은 글이 나올까?"

**시도**: 분량 1200자 미달이면 재시도

**결과**:
- LLM이 빈 곳을 환각으로 채움 (분량 채우려고 거짓 사실 생성)
- `_expand_short_content` 함수가 같은 섹션을 또 만들어 중복 헤딩 발생

**해결**:
- 분량 강제 800자로 완화
- 확장 로직 비활성화 ("짧으면 짧게 두는 게 환각보다 낫다")

**교훈**: **분량 강제는 환각 만드는 주범**. 사실이 부족하면 짧게 끝내는 게 낫다.

## 시행착오 4: "LLM에 가이드 잘 주면 따라할까?"

**시도**: 시스템 프롬프트에 매우 자세한 가이드
```
- PBR < 1배 = 저평가
- PBR 1~2배 = 적정
- PBR > 5배 = 고평가
- PBR 0.49배 같은 1 미만 수치를 "높다"고 잘못 서술하지 말 것
```

**결과**: LLM이 여전히 "PBR 0.49배로 높습니다" 출력. 가이드 무시.

**해결 (3중 안전망)**:
1. 시스템 프롬프트 가이드 (1차 방어)
2. 룰베이스 모순 감지 + 재시도 (2차)
3. 자동 교정 코드 (3차, 최종 안전망)

**교훈**: **LLM은 가이드를 줘도 무시한다.** 코드 검증·교정이 마지막 안전망.

---

## 시행착오 5: "API 키 없으면 시트에 못 쓰나?"

**상황**: 사용자가 "구글 시트 URL 공유했잖아"
**현실**: URL만으로는 Google API에 못 씀. 어떤 형태든 인증 필수.

**시도 순서**:
1. 환경변수에 API 키 → 읽기 전용, 쓰기 불가
2. OAuth 클라이언트 ID → 사용자 직접 발급 필요
3. 서비스 계정 JSON → Cloud Console에서 2분이면 발급
4. Application Default Credentials (gcloud) → gcloud 설치 필요

**최종 선택**: 서비스 계정 + 4단 폴백 (위 1~4 순서대로 시도)

**교훈**: 사용자 친화적 인증 흐름 = 가능한 모든 방법 시도하는 폴백 체인.

## 시행착오 6: "정답글 수준의 글을 어떻게 자동화하나?"

**정답글 사례** (사용자가 보여준 경인전자 분석):
- 시총 472억 + 거래량 12.5만주 = 초저유동성 품절주
- 고퀄 지분 21.53% → LG전자 AI홈 생태계 연결
- 본업 적자 + 영업외수익 흑자 → 진짜 분석 포인트

**시스템에 없던 것**:
- 회사 사업 정보 (네이버 금융 추가 후 해결)
- 지분 시계열 (DART 사업보고서 본문 파싱 후 해결)
- 시장 시황 (KOSPI 추가 후 해결)
- 정답글 패턴 (Few-shot 시스템 프롬프트로 학습)

**핵심 통찰**: **정답글 작성자도 LLM이 아니라 사람.** 검색·DART·뉴스에서 정보 모은 사람이 글을 쓴 것. 시스템이 "검색·DART·뉴스" 자동화하면 LLM이 같은 글을 쓸 수 있다.

---

## 핵심 의사결정 5가지

### 1. **Ollama Local → Gemini Flash Cloud로 전환**

**검토**:
- Local: 무료, 빠름, 인터넷 무관
- Cloud (Gemini Flash): 무료 한도 충분, 글 품질 압도적

**결정**: Cloud 우선 (`AI_MODE=cloud` 기본), Local 폴백.

### 2. **LLM 검증 → 룰베이스 검증 추가**

**검토**:
- LLM 자가 검증: 부정확, 같은 모순 반복
- 룰베이스: 명시적, 안정적

**결정**: 둘 다. 룰베이스가 재시도 트리거, LLM이 수정 작성.

### 3. **재시도 후에도 잔재 → 코드 강제 교정**

**검토**:
- 재시도만 무한정: 비용·시간 폭증
- 코드 교정: 결정론적이지만 표현 변형 위험

**결정**: MAX_RETRIES=2, 그 후 `_auto_fix_contradictions`로 강제 교정.

### 4. **데이터 수집 — DART + 네이버 둘 다**

**검토**:
- DART만: 공식 데이터지만 사업 분야 텍스트 약함
- 네이버만: 풍부하지만 비공식

**결정**: DART = 재무·공시·지분 (사실), 네이버 = 사업 분야 텍스트 (요약). 상호 보완.

### 5. **포맷 — `## 헤딩` vs `**굵은 텍스트**`**

**검토**:
- `## 헤딩`: 표준 마크다운
- `**bold**`: LLM이 `##`와 혼용

**결정**: `## 헤딩` (LLM이 `## **title**` 출력하면 정규식으로 `**` 제거).

---

### 6. **Ollama 로컬 LLM 우선 + Gemini 검증만 무료 사용**

**검토**:
- Cloud 우선: 비용 발생, API 한도 제약
- Local 우선: 무료, 오프라인 운영 가능, 단 품질 약간 낮음
- Gemini 무료 검증: 15 RPM / 1M tokens/day로 검증만 충분히 처리

**결정**: `AI_MODE=local` (exaone3.5:7.8b) 기본 + 검증은 Gemini 무료 티어 별도 활용.

**교훈**: "무료 한도를 파악하고 역할 분리" — 생성은 로컬, 검증은 클라우드 무료분. Self-critique는 AI_MODE=cloud 전용으로 비용 없이 운영.

---

### 7. **종목코드 기반 뉴스 크롤링**

**문제**: 종목명 검색 시 동명이종 회사 뉴스 혼재 (에이프로젠 vs 에이프로젠바이오로직스). 잘못된 뉴스가 LLM 입력으로 주입되면 종목 혼동 환각 발생.

**해결**: Naver Finance 종목탭 URL에 6자리 종목코드 파라미터 사용 (`/item/news.naver?code={code}`) → 정확한 종목별 뉴스.

**결과**: 뉴스 소스를 `naver_finance:{code}`로 태깅 → 트레이서빌리티 확보. 기존 Google News RSS + 네이버 검색과 병행해 3중 뉴스 소스 구조.

## 시행착오 7: "환각 0건"이라 자평한 게 거짓이었다 (가장 큰 교훈)

**증상**: v11 결과를 "환각 0건"이라고 사용자에게 보고. 정량 표에도 "수치 환각 0건"으로 적음.

**현실**: 외부 검토자가 에이프로젠바이오로직스 글에서 **즉시 3가지 오류** 발견:
1. "코스닥" 표기 → 실제 KOSPI
2. "반도체 장비 부품 제조"를 본업으로 단정 → 실제 본업은 의약품+게임 (반도체는 종속회사)
3. "재무 강점: 부채비율·유보율 낮아" → 영업·당기순 모두 적자인 회사

**원인**: 내가 만든 좁은 룰(DART 수치 50%+ 차이)을 통과한 것을 "환각 0건"으로 자평. 실제로는 **수치 환각**만 측정한 부분 지표였음.

**해결 (v12)**:
- DART `corp_cls` 필드로 시장 구분 자동 대조 (KOSPI/KOSDAQ)
- 회사 사업 정보에 없는 분야("반도체/엔터/AI" 등) 본업 단정 시 환각 감지
- 적자 + "재무 강점" / "부채비율·유보율 낮아 안정적" 표현 차단

**교훈**:
- **자기 측정 지표가 좁으면 자기 합리화에 빠진다.**
- "통과율 X%" 같은 자기 평가는 외부 검토자에게 보여주기 전엔 신뢰 못 함.
- 포트폴리오 메트릭에 **"이 기준으로만 측정했다"는 한계 명시** 필수.
- LLM 응용에서 환각은 "수치 환각"보다 "의미론적 환각"이 더 어렵다.

이 시행착오를 어떻게 받아들였는가가 LLM 응용 개발자로서 가장 중요한 자질이라고 생각.

## 시행착오 8: "Gemini 무료 티어 쿼터는 모델별로 독립적이다"

**현상**: gemini-2.0-flash에서 429 (Too Many Requests) 에러 발생. "무료 쿼터를 다 썼구나"라고 판단하고 Gemini 검증 전체를 비활성화할 뻔했음.

**실제 원인 파악**: gemini-2.0-flash의 쿼터가 소진됐을 뿐, gemini-2.5-flash-lite는 별도 쿼터가 남아있었음. Google AI Studio는 모델별로 독립적인 RPM/TPD 한도를 운영함.

**해결**: 모델별 폴백 큐 구현
```python
# gemini_validator.py
FALLBACK_MODELS = [
    "gemini-2.5-flash-lite",
    "gemini-3.1-flash-lite",
    "gemini-flash-lite-latest",
    "gemini-2.5-flash",
]

for model in FALLBACK_MODELS:
    try:
        result = _call_gemini(model, prompt)
        return result
    except Exception as e:
        if "429" in str(e):
            continue  # 다음 모델 시도
        raise
```

**교훈**:
- **API 쿼터는 모델별로 독립적**. 한 모델의 429가 모든 서비스 중단을 의미하지 않음.
- 폴백 설계는 단순 재시도가 아니라 **대체 리소스 탐색**이어야 함.
- 무료 티어를 최대한 활용하려면 모델별 한도를 개별적으로 파악하고 우선순위 큐로 설계.

## 만약 다시 시작한다면

1. **첫날에 ANTHROPIC_API_KEY 검증** — 어떤 모델이 도는지 확인부터
2. **데이터 파이프라인 먼저, LLM 프롬프트 나중** — 데이터 없으면 어떤 프롬프트도 환각 막을 수 없음
3. **검증 단계를 처음부터 설계** — 후처리·정규식·룰베이스를 분리해서 모듈화
4. **정답글 1개를 먼저 수집** — Few-shot 예시 없이 시작하면 LLM이 어디로 갈지 모름
5. **메트릭을 정량화** — "환각률", "검증 통과율", "정답글 도달도" 등을 매 버전마다 기록

## 이 프로젝트로 증명한 것

| 영역 | 증명 |
|---|---|
| **LLM 응용 시스템 설계** | 데이터 → LLM → 검증 → 교정 → 배포의 완결된 10단계 파이프라인 |
| **RAG 깊이** | 단순 챗봇 RAG가 아닌 도메인 특화 **7단** 데이터 소스 (DART 4단 + 네이버 2단 + Obsidian 벡터 DB) |
| **환각 방지 노하우** | 형식·팩트·모순·자동교정·Gemini **5중 검증**. 수치 환각 v3 5/5건 → v13 0/5건 |
| **자동화 완성도** | 월~금 15:40 무인 운영. 21개 상한가 감지 → 이슈 점수 자동 선정 3개 → 작성·검증·배포 30분 |
| **반복 개선 능력** | v1~v13, 매 버전마다 문제 발견·룰 설계·코드 반영·재측정 (GitHub 30+ 커밋) |
| **외부 시스템 통합** | Google Sheets API, Selenium, OAuth/서비스계정, Telegram, chromadb, Ollama |
| **솔직한 문제 해결** | "LLM이 못 한다면 코드가" 실용적 결정. 자기 측정 한계 명시 + 외부 검토 반영 |
| **Obsidian RAG** | 220개 과거 포스트 벡터 DB. 단순 임베딩이 아닌 섹터 필터 2단계 검색 → Few-shot 강화 |
| **API 폴백 설계** | Gemini 모델별 독립 쿼터 파악 → 4단 폴백 큐 구현. 429 에러 → 서비스 중단 없이 자동 전환 |
| **보안 설계** | 하드코딩된 경로/토큰 제거, .gitignore, .env.example 분리 |
