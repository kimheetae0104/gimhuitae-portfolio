01 — 문제 정의

발전 효율 ↑ + NOx 배출 ↓, 두 가지 모델이 필요

발전소는 효율을 극대화하면서 NOx 배출은 환경 규제 한도 안에 묶어야 한다. 운전 변수(온도·압력·유량 등) 사이의 비선형 관계를 학습하는 모델이 필요했다.

이 프로젝트가 풀어야 했던 두 질문은 형태가 달랐다.
① 제어값을 바꾸면 NOx가 어떻게 변할까? 운전 시뮬레이션.
② 지금처럼 두면 5분 뒤 NOx는 얼마가 될까? 실시간 예측.

같은 데이터지만 입력·갱신 주기·평가 기준이 다르므로, 한 모델로 묶지 않고 두 개로 나눠 설계했다.

02 — 모델 1 · 운전 시뮬레이션

1초 데이터는 모델이 베끼기 좋은 형태

1초 간격 데이터의 자기상관이 0.989. 옆 값과 거의 동일해서, 모델이 학습 과정에서 1초 전 값을 그대로 베껴도 점수가 잘 나왔다.

의미 있는 변동만 남기려고 1분 평균으로 다시 묶고, 원시 변수 39개에 파생 10개를 더해 Ridge·LightGBM을 앙상블했다.

DWATT(발전 출력)·TTXM(배기 온도)은 운전 변수에서 직접 따라 나오는 종속 값이라 R² 0.997~0.999. 비선형으로 반응하는 NOx만 R² 0.71에서 멈췄다.

04 — 핵심 난관 · 데이터 누수

R² 0.99는 모델 성능이 아니라 데이터 누수

O₂ 센서를 넣자 R² 값이 0.99로 측정됐다.
CEMS는 측정 NOx를 O₂ 농도로 보정해서 라벨을 만드는데, 그 O₂를 다시 입력에 쓴다는 것을 알게 되었다.
모델이 잘 푼 게 아니라 답을 일부 미리 보고 푼 셈이었다.

CEMS O₂ 보정식 — 환경부·EPA 표준 (ref=15%, 가스터빈) NOx = NOx_raw × (21 − ref) / (21 − O₂)
모델 1 처리

현재 O₂ 제외 → 과거 O₂만

모델 1은 제어값을 가상으로 바꿔 NOx를 시뮬레이션한다. 제어값이 바뀌면 O₂도 함께 변하므로 현재 O₂는 사실상 미래 정보. 현재 값은 빼고 과거 값과 물리식 변환으로 대체했다.

≈0.99→ 누수 제거≈0.71
모델 2 처리

5분 예측에선 현재 O₂ 재포함

5분 뒤 예측 시점에서 현재 O₂는 이미 측정된 값이라 미래 정보가 아니다. 누수가 아닌 걸 확인하고 입력에 다시 포함했다.

0.49→ 재포함≈0.68

05 — 검증과 결과

데이터 누수 없는 검증부터 설계

최종 홀드아웃
앞 14일치는 훈련셋으로 활용하고, 마지막 하루는 테스트셋으로 사용했다.
모델 선택·튜닝 어디에도 쓰지 않아 새 데이터에서의 진짜 성능을 확인했다.
시계열 교차검증
시계열 데이터를 무작위로 나누면 학습 구간에 미래 시점이 포함된다.
과거부터 학습 구간을 점점 넓혀가는 확장 윈도우 방식으로 시간 순서를 유지했다.
학습·검증 간격
학습 구간 끝과 검증 구간 시작 사이에 300초의 간격을 두었다.
직전 값을 그대로 예측값으로 사용해 점수가 실제보다 높게 측정되는 것을 막기 위해서다.
타겟 생성 분리
5분 후 정답값은 각 구간 안의 데이터로만 만들었다.
검증 구간의 미래 값이 학습 구간에 포함되지 않도록 했다.
기준 대비

0.46 → 0.68 (+0.21)

"5분 뒤 = 지금 값"이라고 찍어도 R² 0.46. 절대 점수가 아니라 이 기준선을 얼마나 넘었는지로 평가했다.

한계

R² 0.9가 안 나오는 이유

받은 15일치가 전부 정상운전 구간이라 NOx 변동이 작음.
부하 변동·시동/정지 구간이 있어야 더 높은 R² 가능.

이 프로젝트에서 제일 오래 붙든 건 모델 튜닝이 아니라 "이 값을 입력으로 써도 되나?"라는 질문이었다.
