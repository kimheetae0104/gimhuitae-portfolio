01 · 소개

엔지니어가 AX를 한다.

컨설팅 슬라이드가 아니라, 작동하는 코드로 AI 전환을 만듭니다.

LLM과 에이전트로 기업의 반복 업무를 자동화하는 AX 엔지니어입니다. 모델 정확도보다 현장에서 어떤 일이 어떻게 바뀌었는지를 본질로 봅니다.

문제 정의 → 구조 설계 → 4주 PoC → 평가·운영 전환까지 한 사이클로 끌고 가는 걸 선호합니다. 코드를 짜기 전에 머릿속에 그림을 먼저 그리고, 그 그림이 맞는지 자료 조사와 반복 검증으로 다듬어 나갑니다.

좋은 AX는 도구 선택이 아니라 사람과 워크플로우를 같이 바꾸는 일입니다. 조직에 AI를 안착시킬 때 가장 오래 신경 써야 할 건 LLM이 아니라 사람이라고 봅니다.

일하는 방식

  • 실행이 빠릅니다아이디어 → 동작하는 프로토 사이클을 4주 안에 끝냅니다.
  • 구조부터 그립니다코드 전에 데이터·모듈·흐름을 먼저 설계합니다.
  • 집요하게 검증합니다결과가 안 나오면 가설을 바꿔가며 빠르게 여러 번 시도합니다.
  • 도메인부터 봅니다모델보다 "왜 이 일이 비효율인가"를 먼저 정의합니다.
  • AI-Native로 짭니다Claude Code · Codex · Cursor로 4주 PoC를 돌립니다.

04 · 작업 방식

어떻게 일하나요.

아이디어부터 운영 전환까지 네 단계로 가져갑니다.

01 · 발견

문제 정의

현업 인터뷰로 페인포인트를 한두 개로 좁히고, AI로 풀 가치가 있는지 가치를 추정합니다.

02 · 빌드

4주 프로토타입

LLM·RAG·에이전트·코딩 에이전트(Claude Code 등)로 4주 안에 동작하는 형태를 만듭니다.

03 · 검증

반복 검증

평가셋·로그·만족도로 어떤 가설이 맞는지 빠르게 확인합니다. 가설을 바꿔가며 여러 번 시도합니다.

04 · 운영

운영 전환

가드레일·로그·모니터링을 붙여 안정적인 운영으로 넘기고, 사용 데이터로 다음 반복을 정합니다.

05 · 연락

현업의 가장 힘든 업무 1건, 4주 안에 동작하는 도구로 만들어 보냅니다.

반복되는 문서 작성, 흩어진 자료 검색, 정형화된 응대 업무 — 어떤 업무가 가장 무거우신지 한 줄 알려주시면 4주 안에 동작하는 PoC로 답장드리겠습니다.
