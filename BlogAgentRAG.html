배경

03 · 진행한 일 배경 → 문제 (핵심) → 해결
배경
통째로 LLM에 맡김
초기 시도는 Ollama 로컬 LLM에게
"오늘 상한가 종목 분석 글 작성" 한 줄 프롬프트.
문제 — 핵심
LLM이 모르는 정보를
추측으로 채움
경인전자(가전 리모컨 제조)를 "엔터테이먼트 산업 강점, 매출 1조원"(실제 229억)으로 거짓 서술.

더 똑똑한 모델로 바꿔도 해결 안 됨 — Gemini·Claude도 같은 패턴.
해결
데이터 파이프라인 보강
+ 다층 검증
DART·네이버·뉴스 6개 소스에서 사실을 명시 추출 (RAG)
+ 형식·팩트체커·모순감지·Self-critique 4중 검증
+ LLM이 못 고친 잔재는 코드가 강제 교정
왜 이 방향이 맞았나
정답글 작성자도 LLM이 아닌 사람. 검색·DART·뉴스에서 정보 모은 사람이 글을 쓴 것. → 정보 수집을 자동화하면 LLM이 같은 글을 쓸 수 있다.

04 · 과정 나의 직접적인 액션 · 인사이트
나의 직접적인 액션
액션 01
DART 사업보고서 직접 파싱
OPEN API의 XML 본문에서 "타법인 출자현황 시계열 변동"을 정규식으로 직접 추출 — 정답글 작성자가 가장 중시한 정보(고퀄 지분 21.52% 등)
액션 02
룰베이스 모순 감지 13+ 룰
PBR·PER·적자안정·상한가·시장구분·사업분야·재무강점 등 직접 룰 작성 → 재시도 트리거
액션 03
코드 강제 교정 함수 도입
LLM이 재시도해도 같은 모순을 변형 표현으로 반복하는 현상 발견 → _auto_fix_contradictions로 정규식 강제 교정
액션 04
외부 검토 → 룰 흡수 반복
매 버전 결과를 외부에 노출, 새 환각 유형(시장 구분, 사업 분야 단정)을 룰로 흡수 → v12까지 반복 개선
인사이트
INSIGHT 01
"LLM 크기 ≠ 환각 해소. GPT-4도 데이터 없으면 똑같이 환각. 문제는 모델이 아니라 입력 데이터 부족."
INSIGHT 02
"프롬프트 가이드만으론 안 잡힌다. 코드 검증·교정이 마지막 안전망."
INSIGHT 03 · 가장 큰 교훈
"자기 측정 지표가 좁으면 자기 합리화에 빠진다. '환각 0건'은 외부 검토 전엔 신뢰 못 함."

05 · 결과물 최종 진행 내용 · 포인트
최종 내용
[COLLECT] 6단 RAG (DART 재무·사업보고서·공시·지분 + 네이버 기업개요 + 시황)   →  [GENERATE] Gemini Flash (Few-shot)   →  [VALIDATE] 4중 검증 (형식·팩트·모순·Self-critique)   →  [FIX] 자동 교정   →  [DEPLOY] Sheets·Naver·Obsidian·Telegram
차별화 포인트
POINT 01
도메인 RAG 설계
단순 벡터 임베딩 RAG가 아니라 소스별 최적 추출. DART 사업보고서엔 정규식이 임베딩보다 정확.
POINT 02
시계열 지분 추적
"고퀄 34% → 32% → ... → 21.52%" 시간순 변동에서 최신값만 추출 → 정답글 핵심 트리거 자동 인용.
POINT 03
3중 안전망
프롬프트 가이드(1차) → 룰베이스 검증·재시도(2차) → 코드 강제 교정(3차). LLM이 못 고친 잔재까지.
POINT 04
솔직한 메트릭
"환각 0건"이 아닌 "수치 환각(DART 50%+ 차이) 0건"으로 측정 기준 명시. 의미 환각은 v12에서 룰 보강.

배운점
LESSON 01
LLM 응용의 본질은
"데이터 파이프라인"
모델 교체·프롬프트 튜닝은 데이터 보강 다음 순위.

자기 검증의 한계
같은 LLM은 자기 환각 못 잡고, 좁은 자기 기준은 자기 합리화. 외부 검토자 + 룰베이스 필수.
LESSON 03
솔직한 한계 명시가
신뢰의 기반

07 · 나의 역량 입사 시 기여할 수 있는 부분
느낀점 · 다짐
"환각 방지는 모델이 아니라 시스템 설계의 문제다.
데이터 입력 → LLM → 검증 → 교정 → 배포까지 완결된 파이프라인을 설계할 수 있어야 한다."
앞으로는 LLM을 단일 모델이 아닌 시스템의 한 컴포넌트로 보고, 검증·교정 레이어를 처음부터 설계에 포함시키는 방식으로 일하고 싶다.
배운점 · 다짐
"외부 검토에서 무너지지 않는 지표를 만든다.
자기 측정으로 끝나지 않는다."
매 버전 결과를 외부에 노출해 사각지대를 발견하고, 그 발견을 시스템에 흡수하는 반복 개선 능력을 기여할 수 있다.
